# 结果、机制与局限

## 独立确认

三 seed repair 调用 exact 为 37.40%、36.95%、37.25%，均值 37.20%；父模型、重问及 identity 控制聚合分数为 35.80%。相同聚合分数不表示逐样本预测相同。

配对主要差分 +1.40 pp；相对父模型/identity 的同时 98.333% 区间为 [+0.55,+2.283] pp。初次 640 cohort 的 +2.08 pp 是不同 cohort，不与 2500 混合平均。

## 反证与边界

| 检查 | 结果 | 能得出的结论 |
|---|---|---|
| 静态默认参数删除（事后控制） | 36.55%；repair-static +0.65 pp，95% 区间约 [-0.134,+1.467] | 未证明显著优于该便宜控制 |
| No-call vs Raw | 63.80% vs67.80% | 继承父模型 no-call 退化 |
| Macro vs Raw | 50.50% vs50.975% | 不能宣称整体策略全面改善 |
| 真实 API 执行 | 未运行 | 参考 exact 不等于语义或环境成功 |
| 推理成本 | 4474/2500=1.7896×调用；2.113×prefill | 额外一轮推理是明确成本 |

## 机制审计

跨 seed 共 131 个纠错事件与 47 个退化事件，属于重复测量，不能当 178 个独立请求。57 个纠错事件涉及可选默认参数省略；56 个涉及其他参数省略。收益大量来自参考答案的稀疏参数表示。

错误类型还包括：把 sport 与 goal 混淆、移除与默认排序相反的显式参数、国家码大小写变化，以及没有时间锚点的相对日期。Schema 合法不能证明参数语义正确。

## 成本

- 父模型输入 1,218,927 tokens；候选新增 1,356,607，合计 2,575,534（2.113×）。
- 每部署臂 2500 父查询 +1974 候选查询；不假设不同上下文可共享 prefill。
- 离线实际运行还有原始模型、父重复与多臂审计开销；批量吞吐不等于用户端时延。
